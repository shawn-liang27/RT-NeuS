# RT-NeuS

Real-time neuro-symbolic long-video question answering, built on
[NeuS-QA](https://github.com/UTAustin-SwarmLab/NeuS-QA) (AAAI 2026). Given a video and a
multiple-choice question, the pipeline writes the question as temporal logic, detects its
propositions frame-window by frame-window with a VLM, model-checks the video with Storm, and
hands only the matching segments to a VQA model.

This repository contains both methods on one shared codebase:

| Package | Method | What it adds |
|---|---|---|
| `neusqa` | NeuS-QA baseline | uniform sampling, one VLM call per proposition, upstream frame validator, single segment |
| `rtneus` | RT-NeuS | CLIP-adaptive sampling, KV-cache batched detection, stage-wise validation, multi-segment output |
| `rtneus.ablation` | ablations | any mix of the components above |
| `neus_core` | shared | PULS, target identification, automaton + Storm, VLM scoring, segments, dataset loaders |

## Installation

### Requirements

- Linux with an NVIDIA GPU, 24 GB or more for InternVL2-8B in bf16 (FlashAttention-2 needs Ampere or newer)
- [uv](https://docs.astral.sh/uv/) and Python 3.13 (`uv` installs it)
- `ffmpeg` built with `--enable-libass` (subtitle burn-in and segment cropping)
- An OpenAI API key: PULS and target identification call `gpt-4o`

### Steps

The upstream NeuS-QA install is `uv sync` + `./build_dependency.sh`. Here the build script lives in
`setup/`, and the project itself is installed by `uv sync` (editable, so `import neusqa` / `import rtneus`
work from anywhere):

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh     # if uv is not installed
git clone https://github.com/shawn-liang27/RT-NeuS.git && cd RT-NeuS

# 1. Storm model checker (builds carl-storm + storm-stable into ./vendors)
./setup/build_dependency.sh
source setup/activate_storm_env.sh                  # generated by the build; needed in every shell

# 2. Python environment
uv sync
source .venv/bin/activate

# 3. Packages not in pyproject.toml
uv pip install flash-attn --no-build-isolation      # every InternVL detector loads with flash_attention_2
uv pip install datasets                             # only for Video-MME preparation

# 4. API key (the SLURM launchers read it from .ENV, which is git-ignored)
echo 'OPENAI_API_KEY=sk-...' > .ENV
```

`uv sync` may find a prebuilt `stormpy` wheel for your platform; if it builds stormpy from source
instead, step 1 must have run first so it can find Storm.

### HPC notes (no CLN available)

Load the modules first:

```bash
module load CMake/3.27.6-GCCcore-13.2.0
module load Boost/1.83.0-GCC-13.2.0
module load GMP/6.3.0-GCCcore-13.2.0
module load FFmpeg/6.0-GCCcore-13.2.0
```

stormpy cannot see the existing Storm install under build isolation and tries to rebuild it with CLN,
so install it manually inside the `.venv` before `uv sync`:

```bash
source .venv/bin/activate
.venv/bin/python -m pip install scikit-build-core cmake ninja pathspec pyproject_metadata pybind11
.venv/bin/python -m pip install stormpy --no-build-isolation \
  --config-settings=cmake.args="-DSTORM_USE_CLN_EA=OFF;-DSTORM_USE_CLN_RF=OFF;-DCMAKE_PREFIX_PATH=$LOCAL_INSTALL_DIR;-Dstorm_DIR=$LOCAL_INSTALL_DIR/lib/cmake/storm;-Dpybind11_DIR=$PYBIND_CMAKE_DIR"
uv sync
```

`setup/build_lambda.sh` builds the whole toolchain (CMake, autotools, GMP, Carl, Storm) from source for
machines without modules and writes `setup/activate_storm.sh`; the SLURM launchers source that file.

### Check the install

```bash
python -c "import stormpy; from neusqa import NeuSQA; from rtneus import RTNeuS; print('ok')"
```

## Data preparation

Each benchmark ends up as two directories passed to the pipeline: `--data_dir` (the raw dataset and its
question file) and `--burned_dir` (videos with subtitles burned into the frames, which is what the VLM
sees). Subtitle burn-in needs the libass-enabled ffmpeg; `scripts/dataset_preprocessing/video_mme/test.sh`
checks your ffmpeg build.

### LongVideoBench

```bash
hf download longvideobench/LongVideoBench --repo-type dataset --local-dir "$LVB_DIR"
cd "$LVB_DIR"
cat videos.tar.part.* | tar -xvf - -C .
tar -xvf subtitles.tar
cd -

# burn subtitles for the four categories used in the paper (10-12 h, 10 workers)
python scripts/dataset_preprocessing/longvideobench/burn_subtitles.py \
    --data_dir "$LVB_DIR" --out_dir "$LVB_DIR/burn-subtitles" \
    --categories T3E E3E T3O O3O --mix true
```

`--mix` writes into a timestamped subfolder, e.g.
`$LVB_DIR/burn-subtitles/T3E_E3E_T3O_O3O_mix_2026_01_14_21_55/`; that subfolder is `--burned_dir`.
(`--all true` burns every video into `--out_dir` itself.)

```
$LVB_DIR/                        <- --data_dir
  lvb_val.json                   questions (read by neus_core.datasets.longvideobench)
  videos/  subtitles/
  burn-subtitles/T3E_..._mix_<timestamp>/   <- --burned_dir   (*.mp4)
```

Use `--categories T3E E3E T3O O3O` when running the pipeline too.

### Video-MME

```bash
cd "$VMME_DIR"
hf download lmms-lab/Video-MME --repo-type dataset --local-dir .
unzip subtitle.zip
for f in videos_chunked_*.zip; do unzip "$f"; done       # videos land in data/
cd -

python scripts/dataset_preprocessing/video_mme/prepare_video_mme.py --data_dir "$VMME_DIR"   # writes dataset.json
python scripts/dataset_preprocessing/video_mme/burn_subtitles.py \
    --data_dir "$VMME_DIR" --out_dir "$VMME_DIR/burn-subtitles" \
    --categories "Temporal Perception" "Spatial Perception" "Attribute Perception" "Action Recognition" \
                 "Object Recognition" "OCR Problems" "Temporal Reasoning" "Spatial Reasoning" \
                 "Object Reasoning" "Information Synopsis"
```

```
$VMME_DIR/                       <- --data_dir
  dataset.json   data/*.mp4   subtitle/*.srt
  burn-subtitles/                <- --burned_dir
    dataset.json                 questions the loader reads (see Known issues)
    short/  medium/  long/       burned *.mp4
```

`--categories` here are Video-MME task types; only videos with those task types are burned and listed.
The script `scripts/dataset_preprocessing/video_mme/burn_subtitles.sh` runs both steps.

### MLVU

```bash
hf download MLVU/MVLU --repo-type dataset --local-dir "$MLVU_DIR"
```

No burn-in: the loader reads raw videos. It currently supports the `2_needle` and `3_ego` tasks
(`CATEGORY_DATASET_MAP` in `src/neus_core/datasets/mlvu.py`):

```
$MLVU_DIR/                       <- --data_dir   (--burned_dir is unused)
  json/2_needle.json  json/3_ego.json
  video/2_needle/*.mp4  video/3_ego/*.mp4
```

Run with `--categories 2_needle 3_ego`. The loader also writes `$MLVU_DIR/dataset.json`.

### Custom data

`--benchmark custom --custom_data entries.json` runs on any list of entries shaped like the loaders'
output:

```json
[{"question": "...", "candidates": ["...", "..."], "correct_choice": 0,
  "paths": {"video_path": "/path/video.mp4"}, "metadata": {"id": "q1", "video_id": "video"}}]
```

## Quick example

One video, one question, from Python (needs a GPU and `OPENAI_API_KEY`):

```python
from rtneus import RTNeuS, default_config

pipe = RTNeuS(default_config(), device=0, llm_log_dir="llm_logs")   # loads InternVL2-8B + CLIP once
result = pipe.localize(
    "video.mp4",
    "What does the man in the red jacket do after the subtitle 'welcome back' appears?",
    candidates=["A. sits down", "B. waves", "C. leaves", "D. laughs"],
    sample_id="demo",
)

result.puls["specification"]   # e.g. "subtitle_welcome_back" U "man_in_red_jacket_waves"
result.target_identification   # frame window chosen by the LLM, with its explanation
result.segment_mode            # "intersect" (Until spec) or "union" (Until-free spec)
result.segments                # [(start_frame, end_frame), ...]; [-1] means use the whole video
```

- The baseline is the same call: `from neusqa import NeuSQA; NeuSQA(device=0).localize(...)`.
- Candidate-style questions (MLVU, Video-MME) work better with the multi-operator PULS:
  `RTNeuS(default_config(puls="multi"))`.
- Reuse loaded models across pipelines: `RTNeuS(config, detector=..., clip_model=...)`.
- Skip the GPT-4o calls on reruns: `pipe.localize(..., puls=saved_puls, target_identification=saved_tid)`.
- `measure_metrics=True` fills `result.metrics` with per-stage timings and VLM answer diagnostics.

The same thing from the command line, on the first 1/100 of LongVideoBench:

```bash
python scripts/localize.py --pipeline rtneus --config configs/rtneus_lvb.json --benchmark lvb \
    --data_dir "$LVB_DIR" --burned_dir "$LVB_BURNED_DIR" --categories T3E E3E T3O O3O \
    --output_dir results/demo --current_split 1 --total_splits 100 --device 0 --measure_metrics
```

## Full benchmark inference

`scripts/localize.py` runs one split of a benchmark on one GPU:

| Flag | Meaning |
|---|---|
| `--pipeline` | `neusqa`, `rtneus` or `ablation` |
| `--config` | JSON config, see below |
| `--benchmark` | `lvb`, `mlvu`, `video_mme`, `custom` |
| `--data_dir`, `--burned_dir`, `--categories` | from [Data preparation](#data-preparation) |
| `--current_split`, `--total_splits` | which contiguous slice of the questions to run |
| `--device` | CUDA device index (`--port_number` is an alias used by the launchers) |
| `--vlm_model_name` | override the config's VLM, e.g. `InternVL2-8B` |
| `--measure_metrics` | write per-question timings to `full_time_metrics.json` |
| `--save_crop` | also cut the segments into videos with ffmpeg; only for the cropped-video evaluation path (NeuS-QA, ablations), RT-NeuS does not need it |

| Config | Use for |
|---|---|
| `configs/neusqa.json` | NeuS-QA baseline on any benchmark |
| `configs/rtneus_lvb.json` | RT-NeuS on LongVideoBench |
| `configs/rtneus_lvb_multi.json` | RT-NeuS on LongVideoBench with the multi-operator PULS |
| `configs/rtneus_mlvu.json`, `configs/rtneus_video_mme.json` | RT-NeuS on MLVU / Video-MME (multi-operator PULS) |
| `configs/ablation/*.json` | ablations, see [Ablations](#ablations) |

Every field of a config is a `PipelineConfig` field (`src/neus_core/config.py`); unknown keys are
rejected. The most relevant ones:

- `puls`: `single` (one Until chain, as NeuS-QA) or `multi` (multi-operator; builds the spec from the answer
  candidates when the question has no events, e.g. `F a & F b & F c` for order questions)
- `segment_mode`: `single` (NeuS-QA), `intersect` (P->Q handover ∩ automaton), `union` (every detected
  event ∪ automaton) or `auto` (intersect for specs with Until, union for Until-free specs)
- thresholds (`vlm_detection_threshold`, `detection_threshold`, `tl_satisfaction_threshold`),
  `clip_threshold`, `bridge_seconds` / `context_seconds` / `handover_tolerance_seconds`

### Multi-GPU runs (SLURM / plain bash)

`scripts/slurm/*.sh` start one `localize.py` worker per split on consecutive GPUs and wait for all of
them. Run them from the repo root:

```bash
bash scripts/slurm/rt_neus_lvb.sh <first_gpu> <run_number>
bash scripts/slurm/rt_neus_ablation.sh <first_gpu> <run_number> <ablation_type>   # e.g. batched_adaptive
```

Edit the variables at the top of each launcher first. They still contain the original authors' paths:
`JOB_DIR`, `DATA_DIR`, `BURNED_DIR`, `OUT_DIR`, `MODEL`, `CATEGORIES`, `TOTAL_SPLITS`, `BENCHMARK`.

| Launcher | Pipeline / config |
|---|---|
| `neus_qa_lvb.sh`, `neus_qa_mlvu.sh` | NeuS-QA |
| `rt_neus_lvb.sh`, `rt_neus_lvb_multi.sh`, `rt_neus_mlvu.sh`, `rt_neus_video_mme.sh` | RT-NeuS |
| `rt_neus_ablation.sh`, `nsvs_only_naive.sh` | ablations |
| `nsvs_only_single_split*.sh`, `nsvs_only_single_test.sh` | single-GPU debugging runs |

### Outputs

```
<output_dir>/                         one split
  run_config.json                     exact settings of this run
  nsvqa_output/nsvqa_output_<split>.json
  postprocess_output/postprocess_output_<split>.json   (--save_crop)
  postprocess_output/cropped_videos/<id>.mp4          (--save_crop)
  llm_conversation_history/<id>/      PULS and target-ID transcripts
  full_time_metrics.json              (--measure_metrics)
```

Each entry in `nsvqa_output_<split>.json` is the benchmark entry plus:

| Field | Content |
|---|---|
| `puls` | `proposition`, `specification`, transcript path (+ `is_valid`, `raw_output` for multi PULS) |
| `target_identification` | `frame_window` (e.g. `[start_time - 5, end_time + 10]`), `explanation` |
| `nsvs.output` | raw frames of interest before padding |
| `nsvs.indices` | per temporal stage, the frame indices where its propositions were detected |
| `nsvs.segment_mode` | segment mode actually used |
| `frames_of_interest` | final `(start, end)` frame ranges sent to VQA; `[-1]` = full video |
| `metadata.error` | set when PULS or localization failed (the entry is still kept, as full video) |

`full_time_metrics.json` has per-question stage timings (`PULS_time`, `Target_ID_time`, `video_IO_time`,
`NeuS_time`, `per_frame_window_detection_time`, `model_checks_time`, ...), sampling statistics, and
`yes_no_mass`: how much probability the VLM put on "Yes"/"No" (values well below 1 mean it did not follow
the Yes/No answer format).

## Evaluation with lmms-eval

Accuracy comes from running a VQA model with [lmms-eval](https://github.com/EvolvingLMMs-Lab/lmms-eval)
on only the localized part of each video. There are two ways to hand the localization over:

| | Cropped videos (NeuS-QA style) | Segment indices (RT-NeuS style) |
|---|---|---|
| How | ffmpeg cuts `frames_of_interest` into a new `.mp4` per question (`--save_crop`) | the question file carries `frames_of_interest`; the VQA model samples frames only inside those ranges |
| lmms-eval | task YAML pointed at the cropped videos | patched tasks + models that accept `{"path": ..., "segments": [[start, end], ...]}` ([third_party/lmms-eval](third_party/lmms-eval/README.md)) |
| Extra cost | an ffmpeg re-encode and a video copy per question | none |
| Prep script | `prepare_lmms.py` (LongVideoBench), `prepare_lmms_video_mme.py` (Video-MME) | `prepare_lmms_segments.py` (all three) |
| Used for | NeuS-QA baseline, ablations | **RT-NeuS** |

Segment indices are the RT-NeuS evaluation path: no re-encoding, and every patched model samples its
usual number of frames uniformly across the concatenated kept segments (the same frames uniform
sampling of the cropped video would pick). RT-NeuS needs no cropping on any benchmark: run
localization **without** `--save_crop`, then build the question file with `prepare_lmms_segments.py`.
`frames_of_interest` is `[-1]` when the whole video should be used (localization failed or found
nothing); the prep script turns that into the full video.

### Steps

1. Run localization for every split (RT-NeuS: no `--save_crop`).
2. Collect the splits into one lmms-eval question file, segments included; `--out` is where the run
   script in step 4 looks:

   ```bash
   # LongVideoBench: question file next to the run, videos referenced by absolute path
   python scripts/evaluation/prepare_lmms_segments.py --benchmark lvb --run_dir <run> --data_dir "$LVB_DIR" \
       --out <LOG_BASE_PATH>/lmms/neusqa/lvb_val.json
   # Video-MME
   python scripts/evaluation/prepare_lmms_segments.py --benchmark video_mme --run_dir <run> --data_dir "$VMME_DIR" \
       --out "$VMME_DIR/data/rt-neus/experiment_<n>.json"
   # MLVU
   python scripts/evaluation/prepare_lmms_segments.py --benchmark mlvu --run_dir <run> \
       --out "$MLVU_DIR/rt-neus/experiment_<n>.json"
   ```

   `<run>` holds `split_1 ... split_N`. Add `--full_video` (and point `--out` at the `original` location)
   for the full-video comparison, again without copying videos. The cropped-video scripts
   (`prepare_lmms.py`, `prepare_lmms_video_mme.py`, `prepare_lmms_mlvu.py`) are kept for the NeuS-QA
   baseline and ablations; their paths are hard-coded at the top.
3. Install the patched lmms-eval: upstream commit `6cc2f72` + your experiment patch + the follow-up that
   adds LongVideoBench segments:

   ```bash
   git clone https://github.com/EvolvingLMMs-Lab/lmms-eval.git && cd lmms-eval
   git checkout 6cc2f72380415d76e48317e119e48e7135fefd20
   git apply --whitespace=nowarn ../third_party/lmms-eval/rtneus_segments.patch
   git apply ../third_party/lmms-eval/rtneus_segments_lvb.patch
   uv pip install -e . && cd ..
   ```

   [third_party/lmms-eval/README.md](third_party/lmms-eval/README.md) lists every change and its known
   problems.
4. Run it. `scripts/evaluation/lmms/run_lmms_{lvb,mlvu,video_mme}.sh` point the task YAML at the
   question file and launch on 4-6 GPUs (edit the paths and `MODEL*` variables at the top first):

   ```bash
   bash scripts/evaluation/lmms/run_lmms_mlvu.sh <type> <experiment_number> <neusqa|original>
   ```

   which runs

   ```bash
   accelerate launch --num_processes=6 --mixed_precision=bf16 -m lmms_eval --model internvl2 \
       --model_args pretrained=OpenGVLab/InternVL2_5-8B,attn_implementation=flash_attention_2 \
       --tasks mlvu_dev --batch_size 1 --log_samples --output_path <out>   # or longvideobench_val_v / videomme
   ```

   `neusqa` evaluates on the localized segments, `original` on the full videos. VQA models used:
   `internvl2`, `qwen2_5_vl`, `llava_vid`, `llava_onevision`, `videollama3`, `gemma3`.
5. Summarize runtimes: `python scripts/evaluation/aggregate_metrics.py <run_dir> <lvb|mlvu|video_mme>`.

`scripts/evaluation/vllm_serve.sh` hosts a VQA model with vLLM if you prefer a server.

## Ablations

`--pipeline ablation --config configs/ablation/<name>.json` builds the pipeline from the same components
as NeuS-QA and RT-NeuS. The configs are the original ablation files and load unchanged:

| Key | Values |
|---|---|
| `vlm_method` | `sequential` (one call per proposition), `batched` (one batched call), `kv_cache` (RT-NeuS) |
| `read_video_method` | `uniform`, `adaptive` (RT-NeuS), `stage1` (CLIP relevance only), `stage2` (dedup only) |
| `return_segments` | `false` -> NeuS-QA single segment, `true` -> `intersect` |
| `adaptive_gt` | record high-confidence windows (`gt_frames` in the metrics) |
| `frame_validator` | `upstream` (default, as in the ablation runs) or `stage` |

Any `PipelineConfig` field can be added to override engine settings. Ablation defaults match the
original ablation runs: single-chain PULS, 10 s bridge/context.

## Repository map

| Pipeline stage | Code |
|---|---|
| Question -> propositions + LTL (PULS) | `src/neus_core/puls/` (single Until chain), `src/neus_core/puls_multi/` (multi-operator, candidates) |
| Target identification (time window around the event) | `src/neus_core/target_identification.py` |
| Frame sampling | `src/neusqa/sampling.py` (uniform), `src/rtneus/sampling.py` (CLIP-adaptive), `src/rtneus/ablation/sampling.py` |
| Proposition detection (InternVL yes/no) | `src/neus_core/vlm/internvl.py` (base, preprocessing), `src/neusqa/vlm.py`, `src/rtneus/vlm.py` (KV cache), `src/rtneus/ablation/vlm_batched.py` |
| Yes/No confidence + calibration | `src/neus_core/vlm/yes_no.py`, `src/neus_core/vlm/sigmoid.py` |
| Frame validation | `src/neusqa/frame_validator.py` (upstream), `src/rtneus/frame_validator.py` (stage-wise) |
| Video automaton + Storm model checking | `src/neus_core/model_checker/` |
| Window loop tying it together | `src/neus_core/pipeline.py` (`run_localization`, `LocalizationPipeline`) |
| Segment output, target-window padding | `src/neus_core/segments.py` |
| Benchmarks + ffmpeg cropping | `src/neus_core/datasets/` |
| Presets | `src/neusqa/pipeline.py`, `src/rtneus/pipeline.py`, `src/rtneus/ablation/pipeline.py` |

Other folders: `configs/` run configs, `scripts/` (CLI, launchers, data prep, evaluation, analysis
notebooks), `third_party/lmms-eval/` the lmms-eval patch for segment inputs, `paper/` figures and plotting scripts, `setup/` Storm build and environment scripts,
`docs/upstream_README.md` the original NeuS-QA README.

To add a component, implement it next to its siblings and select it in a preset or in
`AblationPipeline`: a detector subclasses `InternVLDetector` and implements `score()`, a sampler returns
the dict documented in `run_localization`, a validator implements `validate_frame()` (and optionally
`stages` / `stage_of()` for multi-stage specs).

## Tests

About 350 CPU-only tests; a scripted detector replaces InternVL and Storm comes from the stormpy wheel, so
they run on a laptop without the GPU stack:

```bash
uv run --no-project --python 3.12 --with pytest --with numpy --with torch --with tqdm --with pillow \
    --with opencv-python-headless --with stormpy --with openai python -m pytest
```

- `tests/test_frame_validator.py`: upstream validator (frozen behaviour) and the stage-wise validator
- `tests/test_grounding_and_segments.py`: Yes/No scoring (including equivalence with upstream's vLLM
  scoring), handover / target-window helpers, adaptive sampler
- `tests/test_pipelines.py`: engine, presets, configs, CLI, and a replay of the pre-restructure NeuS-QA
  code checking the new `neusqa` path returns identical segments. It needs a clone of the NeuS-QA repo
  (below) via `NEUSQA_REPO=/path/to/NeuS-QA`; without it that test is skipped

## Known issues and open questions

- **lmms-eval patch: remaining known bugs** (details in
  [third_party/lmms-eval/README.md](third_party/lmms-eval/README.md)): LLaVA-OneVision passes segment
  frames and full videos in different tensor layouts; VideoLLaMA3's custom loader fails on plain paths;
  MLVU picks a random gold letter when the answer is not among the candidates. The Video-MME task reads
  the raw `data/<videoID>.mp4` while RT-NeuS indexes the subtitle-burned video, which assumes burning
  kept every frame.
- **Probability threshold not applied in model checking** (inherited from upstream).
  `StormModelChecker.qualitative_result_eval` returns true if *any* automaton state satisfies the spec,
  so `tl_satisfaction_threshold` has no effect. The correct check, `P>=p [ X φ ]` from the initial
  state, is stricter and would remove detections; whether that causes false negatives depends on the VLM
  confidence distribution (check `yes_no_mass` and the confidences first).
- **GPU checks not yet done after the refactor:** confirm `yes_no_token_ids(tokenizer)` finds the
  InternVL Yes/No tokens, that the three detectors give similar confidences on the same window, and that
  `yes_no_mass` is close to 1. The batched and KV-cache detectors tokenize without the BOS token while the
  sequential one adds it.
- **PULS formulas that reference events missing from their own proposition list** (~1-5% of
  questions, e.g. `... U woman leaves the path`) leave raw text in the spec. They are not marked invalid
  yet.
- **Video-MME uses one question per video.** `video_mme/burn_subtitles.py` de-duplicates by `videoID` when
  writing `dataset.json`, so only the last question of each video is evaluated. Unclear whether this was
  intended.
- **MLVU preparation scripts are leftovers.** `scripts/dataset_preprocessing/mlvu/` (`prepare_mlvu.py`,
  `burn_subtitles*.sh`, the notebook) were copied from Video-MME and do not prepare MLVU; only the HF
  download above is needed.
- **Hard-coded paths** remain in `scripts/slurm/`, `scripts/evaluation/`, `setup/activate_storm.sh` and
  the notebooks.
- `nsvs_only_naive.sh` accepts ablation type `sequential`, which has no config in `configs/ablation/`.

## Reproducing pre-restructure results

The experiments so far were produced by the earlier code in
[shawn-liang27/NeuS-QA](https://github.com/shawn-liang27/NeuS-QA) (branch `neus-improve-efficiency`),
from which this repository was restructured. The restructure fixed several
bugs that change behaviour for both methods (VLM confidence now follows upstream's Yes/No scoring,
stage-wise frame validation, ordered P->Q handover, `segment_mode: auto`, PULS keyword handling, CLIP
fallback, event gaps in seconds, failed-PULS questions kept as full video). To reproduce those numbers
exactly, use the last pre-restructure commit of that repo:

```bash
git clone -b neus-improve-efficiency https://github.com/shawn-liang27/NeuS-QA.git
cd NeuS-QA && git checkout 4f07cc8      # old layout: scripts/lmms_eval/nsvs_only*.py
```

New comparisons should rerun both NeuS-QA and RT-NeuS on the current code.
